# ABX 盲听测试（本地 Web 应用）

一个完全在本机运行的音频 ABX 盲听工具：上传 A、B 两段**同格式**音频，服务端
随机生成每题的 X（X 可能是 A 也可能是 B），答题过程中映射完全隐藏；逐题作答、
可随时返回修改，最终提交后一次性揭示正确率与逐题映射。

- 后端：Node.js + Express（上传流式落盘，音频不进内存）
- 前端：原生 HTML/CSS/JS + 浏览器 **Web Audio API**（`AudioContext` 解码播放）
- 存储：音频与会话仅保存在**本机** `data/` 目录，默认 24 小时自动清理，不依赖任何外部服务

## 功能说明

1. **上传**：选择 A、B 两段同格式音频（wav / flac / mp3 / m4a / aac / ogg / oga / opus / webm），
   可选题目数量（2–20，默认 10）。浏览器先读取两段时长并随上传一并提交。
2. **统一时间轴**：以两段音频中**较短时长**作为播放时间轴，较长音频超出部分不播放，
   保证三路切换时位置一一对应。
3. **随机题序**：每题的 X 由服务端用密码学随机数（`crypto.randomInt`）独立取自 A/B，
   映射只保存在服务端，提交前的任何接口都不会返回。
4. **试听**：可在 **A / X / B** 三路之间任意切换——
   - 切换时**保持当前播放位置**；
   - 播放中切换 → 新轨从同一位置无缝续播；暂停中切换 → 保持暂停；
   - 可拖动进度条定位（对三路同时生效）。
5. **逐题作答 / 返回修改**：题目导航点显示作答状态，可前后翻题、随时改答案。
6. **提交揭示**：一次性提交全部答案后，显示正确率、判定参考以及每题
   “你的判断 / X 实际是 / 对错”的完整映射；提交后该会话不可再次作答或试听 X。
7. 快捷键：`1/2/3` 切 A/X/B，`A/B` 作答，`空格` 播放暂停，`←/→` 翻题。

## 一条命令启动

### 方式一：Docker Compose（推荐，无需本机安装 Node）

```bash
docker compose up --build -d
```

自动完成镜像构建、依赖安装与启动。访问：

> **http://localhost:3000**

如需更换宿主机端口：

```bash
ABX_PORT=8080 docker compose up --build -d   # 然后访问 http://localhost:8080
```

停止：`docker compose down`（音频数据保留在本机 `./data`）。

### 方式二：本机 Node.js（需要 Node ≥ 18）

```bash
npm install && npm start
```

访问：

> **http://localhost:3000**

## 端口与配置（环境变量）

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | 服务监听端口（容器内固定 3000，宿主机映射用 `ABX_PORT`） |
| `HOST` | `0.0.0.0` | 监听地址；仅想本机访问可设为 `127.0.0.1`（本机 Node 启动时） |
| `DATA_DIR` | `data` | 音频与会话存储目录（相对项目根目录） |
| `SESSION_TTL_MS` | `86400000`（24 小时） | 启动时清理超过该时长的会话 |
| `MAX_UPLOAD_MB` | `1024` | 单个音频文件大小上限（MB） |

本机运行且不希望局域网可访问：

```bash
HOST=127.0.0.1 npm start
```

## 数据与隐私

- 上传的音频以 `a<扩展名>` / `b<扩展名>` 保存在本机 `data/sessions/<随机会话ID>/`，
  不经过任何第三方；X 音频由服务端在内部直接返回对应文件，响应中不含可推断来源
  的文件名或元数据。
- 会话 ID 为随机 32 位十六进制串；答案在提交前只保存在浏览器本地（localStorage），
  刷新导航不会丢失同页答案，提交后自动清除。
- 结果页提供「删除本机音频与会话」按钮（`DELETE /api/sessions/:id`）；
  也可以直接删除 `data/` 目录。
- 服务每次启动会自动清理超过 TTL 的旧会话。

## API 概览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/sessions` | multipart 上传 `a`、`b` 及时长、题量，创建会话并生成随机题序 |
| `GET` | `/api/sessions/:id` | 会话信息（提交前不含映射） |
| `GET` | `/api/sessions/:id/audio/:track` | `a`、`b` 或 `q0`、`q1`… 即每题的 X（统一中立响应头） |
| `POST` | `/api/sessions/:id/submit` | 提交答案数组，返回正确率与逐题映射 |
| `DELETE` | `/api/sessions/:id` | 删除本机该会话与音频 |

> 说明：浏览器端必然能拿到 A、B 两段音频本身（这是试听功能的前提），
> 因此“盲”的含义是**应用层面不提供任何 X→A/B 的对应线索**（映射在提交前
> 不下发、响应标识中立），适合同机自我盲测，而非对抗恶意抓包的考试场景。
